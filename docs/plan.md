The intended flow is **Google sign-in → explicit Gmail consent → admin approval → configure → Start**. Already-approved users skip the approval wait. No mailbox reads or actions occur before approval and an explicit Start. New accounts default to dry run; confirmed live mode must also be available. Stop, denial, expiry and restart prevent new work; requests already in flight may finish.

Prioritize the shortest safe route to that pilot: protect and recover the real beta's data, meet the applicable Google privacy and security requirements, deploy the current beta without changing the demo, then test the owner's real inbox before inviting reviewers. Defer public-release features and broader infrastructure that are not necessary for the pilot. Google documents a verification exception for projects in Testing with added test users, but warnings and limited refresh-token lifetimes apply; policy compliance still matters and the exception must not be assumed for wider use.
